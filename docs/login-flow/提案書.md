## A. ゲーム全体のフロー案

```
ログイン画面
   ↓
物語画面（クリックで進む）
   ↓
モード選択画面（物語画面をそのまま背景に）
   ├─ カードモード（条件分岐をカードで学ぶ）
   └─ 組み合わせモード（語彙を組んでプログラミングの基礎を学ぶ ＝ 語彙遠征）
```

### 意図
- ログイン直後にいきなりゲームへ入るのではなく、**モードを選ぶ画面**を挟む。
- モード選択は **新規画面**として追加するので、既存のゲーム画面の中身は触らない（＝担当間で衝突しにくい）。

### 論点
- **物語画面を「クリックで進む」**にする案は、物語画面（BattleScreen）の中身に触れるため、
  ゲーム画面担当の領域。→ 実装前に担当と要相談（勝手に変えない）。
- モード選択画面のUI（カード2枚のデザイン）は別途モックを用意。

## C. 語彙遠征（WordQuest）UX改善案 ※実装保留

> 下記はゲーム画面担当の領域。良い改善だと思うが、**提案として共有し合意後に入れる**。
> （バグ修正である「スロット2に戻る」問題だけは先に修正済み。→ `更新内容.md` 参照）

### (b) 作戦文が完成したら「作戦を実行する」ボタンを軽く点滅
- 目的: 完成後に何をすればいいか分からない状態を防ぎ、実行を促す。
- 実装イメージ:
  - 全作戦文が有効（`validatePlan` が全て valid）になったらボタンに `is-ready` クラスを付与。
  - CSS でゆっくり点滅（`prefers-reduced-motion` 配慮）。

### (c) 文法エラーのスロットを強調（赤枠）
- 目的: エラー文だけだと、6スロットのどこが原因か分かりにくい。
- 実装イメージ:
  - 検証結果 `SentenceValidation` は既に **`missingSlot`（エラー箇所）を持っている**ので、
    そのスロットのボタンに `is-error` クラスを付けて赤枠にするだけで実現可能。
- 補足: データは既に揃っているので実装コストは小さい。
