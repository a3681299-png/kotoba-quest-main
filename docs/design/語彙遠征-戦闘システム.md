対象: 組み合わせモード（語彙遠征 / WordQuest）の戦闘ルール

## 1. コアモデル（変更後）

| 項目 | ルール |
|---|---|
| **作戦文の数** | 1階層＝**2文**スタート、階層が進むごとに **+1文**（1階層2文／2階層3文／…） |
| **実行** | 書いた文を**上から全部実行**する（条件一致の1文だけ、ではない）。攻撃を2文書けば2回攻撃 |
| **コスト（エナジー）** | 文の実行に**コスト**を消費。**使えるコスト上限はステージ・階層が進むごとに増える** |
| **コスト回復** | ターン終了で上限の**一定割合を回復**＋**専用の回復行動**でも回復できる |
| **カードの使用回数** | カードごとに**1戦闘／1ターンの使用上限**を設定（殴り連打＝DPSゲー化を防ぐ） |
| **条件（どんな時）の役割** | 分岐選択ではなく「**不発なら無駄撃ち回避＝コストを使わない**」ゲート（下記2） |

### なぜコスト＋使用回数を入れるか
全文実行にすると「攻撃カードを並べるだけ」のDPSゲーになりやすい。**コスト（総量制限）**と
**使用回数（カード別制限）**の二重の制約で、「限られた資源で何を撃つか」の選択を作る。

---

## 2. 条件（分岐）の再定義 ※設計の肝・要確認

全文実行でも、**条件を満たさない文は発動しない＝そのコストも消費しない**とする（推奨）。すると：

- 条件は「どの枝を選ぶか」ではなく「**無駄撃ちを避ける最適化**」になる。
  - 例：`敵が近くにいる時→近接攻撃` と `敵が遠くにいる時→遠距離攻撃` を両方書いても、
    実際に発動＆コスト消費するのは**今の状況に合った方だけ**。
- → **論理（条件分岐）の学びは消えず**、資源管理と両立する。ここが「学習の背骨」を保つ要。

> ⚠️ 要オーナー確認：「条件不成立の文はコスト非消費」で合意が取れるか。ここが崩れると論理の意味が薄れる。

## 3. 成長カーブ（仮・要調整）

「文数」「エナジー上限」がステージ（階層内）と階層でともに増える例。数値は**仮**。

| 階層-ステージ | 使える文数 | エナジー上限(仮) | 主眼 |
|---|---|---|---|
| 1-1（チュートリアル）| 2 | 3 | 操作を覚える |
| 1-2 | 2 | 3 | 条件分岐 |
| 1-3 | 2 | 4 | 〃 |
| 1-4（階層ボス）| 2 | 4 | 総まとめ |
| 2-1 | 3 | 5 | 先制を知る |
| 2-4（階層ボス）| 3 | 6 | 複合 |
| 3階層〜 | 4〜 | 7〜 | 回数制限・行動連動 |

- **上限式（案）**：`エナジー上限 = 基礎3 +（階層-1)×2 + (ステージ-1)×1`（要バランス調整）
- ターン回復（案）：ターン終了で**上限の50%**を回復（切り上げ）。
- 専用回復行動（案）：`コストをためる`＝そのターンは他を控えめにして次ターンのエナジーを底上げ。

## 4. データ構造への落とし込み（案）

新規はゲーム内部（`types.ts`／`battle.ts`／run状態／UI）。＝オーナー領域の実装。

**カード（語彙）側に追加**
```
cost: number            // 実行時に消費するコスト
usesPerBattle?: number  // 1戦闘の使用上限（未指定＝無制限）
usesPerTurn?: number    // 1ターンの使用上限（未指定＝無制限）
```

**プレイヤー／run 状態に追加**
```
energy: number          // 現在のコスト
energyMax: number       // 上限（ステージ・階層で成長）
```

**`battle.ts` の実行ループ変更点**
1. 文を上から見る。**条件を満たさない文はスキップ（不発・コスト非消費）**。
2. 満たす文は、`energy >= cost` かつ 使用回数が残っていれば実行し、`energy -= cost`／使用回数を減らす。
   足りなければ不発（ログに「コスト不足で不発」）。
3. ターン終了時に `energy` を上限の一定割合まで回復。
4. 新アクション：`コスト回復`（`energy` を回復する専用行動）。

**戦闘開始時**：`energyMax` はそのステージ/階層の値で設定、`energy = energyMax` で開始。

## 5. 教育の軸

- **背骨＝プログラミング論理**（条件で無駄撃ちを避ける＝分岐の意味は維持）
- **上乗せ＝資源管理**（限られたコスト・使用回数で最適な手を選ぶ）
- 「論理パズル」から「資源管理戦闘」へ**寄りすぎない**よう、条件の役割（2章）を守るのが前提。
